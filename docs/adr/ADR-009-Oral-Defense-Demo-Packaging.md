# ADR-009: 碩士學位口試展示系統獨立模組化與雙軌運行架構 (Oral Defense Demo Packaging & Dual-Track Runtime Architecture)

## 狀態
**Status:** 已接受 (Accepted) - 2026-10

## 背景與問題 (Context)
在碩士學位論文口試的成果驗證環節中，需要向評審委員進行互動式的模型推薦推論與忠實度檢測展示。然而，現場展示面臨以下核心工程與環境挑戰：

1. **運算資源與硬體限制**：
   本研究所建構之協同知識圖包含逾 47 萬個節點與 720 萬條邊，圖注意力神經網路需要大量顯存進行圖卷積與注意力權重聚合。口試現場使用的輕薄型筆記型電腦缺乏獨立圖形處理器，無法在本機載入全圖權重並執行即時推論。
2. **會場網路波動與依賴風險**：
   若完全依賴遠端工作站進行推論連線，口試會場之網路品質、防火牆阻擋或連線中斷將導致展示停擺，存在致命的單點故障風險。
3. **程式碼模組邊界不清晰**：
   展示系統之推論端點、靜態網頁、資料萃取工具與啟動腳本原先分散於核心模型目錄 (`src/demo/`) 與專案根目錄，導致核心演算法與展示外殼邊界模糊，缺乏獨立發布與維護之模組化架構。

---

## 決策內容 (Decision)

### 1. 獨立模組化封裝與目錄解耦 (Packaging Isolation)
將展示系統之完整代碼、靜態資源與執行腳本自 `src/demo/` 完整遷移至專案頂層之獨立模組目錄 `demo/`：
- **後端推論伺服器 (`demo/server.py`)**：基於 FastAPI 建構推論端點，支援動態路徑探測與快取自動尋址，解耦本機私有路徑。
- **資料萃取工具 (`demo/export_demo_cases.py`)**：負責自評估產出中萃取五組典型案例與五百位評估名冊。
- **純靜態前端介面 (`demo/web/`)**：包含主頁面、樣式表、腳本邏輯與快取資料，具備獨立渲染能力。
- **專屬雙擊啟動腳本 (`demo/run_server.bat`、`demo/run_offline_laptop.bat`)**：遵循純 ASCII 外殼與動態路徑錨定規範。
- **專案根目錄引導外殼**：保留頂層雙擊腳本並直接轉發至 `demo/` 內部腳本，維持使用者既有使用習慣。

### 2. 雙軌展示機制設計 (Dual-Track Runtime Architecture)
為兼顧展示深度與口試現場之絕對穩定性，設計連線推論與完全離線雙軌運行架構：

```
                    ┌──────────────────────────────┐
                    │    碩士學位口試展示系統      │
                    └──────────────┬───────────────┘
                                   │
         ┌─────────────────────────┴─────────────────────────┐
         │                                                   │
         ▼                                                   ▼
┌──────────────────────────────┐            ┌──────────────────────────────┐
│     軌道一：連線推論模式     │            │   軌道二：完全離線展示模式   │
├──────────────────────────────┤            ├──────────────────────────────┤
│ 運作主機：遠端桌上型工作站   │            │ 運作主機：現場筆記型電腦     │
│ 端口規範：監聽 8501 端口     │            │ 執行方式：本機開啟靜態 HTML  │
│ 服務能力：全庫任意使用者推論 │            │ 資料來源：demo_cases_data.js │
│ 穿透支援：Cloudflare Tunnel  │            │ 安全特性：零跨來源阻擋 (CORS)│
└──────────────────────────────┘            └──────────────────────────────┘
```

1. **連線推論模式**：
   - 伺服器部署於高效能運算主機，載入 8 款推薦模型（KGAT 各深度、消融實驗組與基準模型）。
   - 採用預先計算之全圖特徵嵌入快取與矩陣內積推論，推論耗時小於 1 毫秒。
   - 透過 8501 端口對外提供服務，可透過安全穿透隧道供口試筆電進行全庫互動展示。
2. **完全離線展示模式**：
   - 筆記型電腦在無網路連線環境下，直接以瀏覽器開啟靜態介面。
   - 資料載入跳過非同步網路請求，直接讀取全域注入物件 `window.DEMO_CASES_DATA`，徹底規避瀏覽器本地檔案協定之跨來源資源共用限制。
   - 預載五組典型學術案例與五百位評估名冊，完整展現所有核心圖拓樸與忠實度指標。

### 3. 高效尋路演算法與拓樸因果狀態機 (Algorithm & State Machine)
1. **CSR 局部閉環向量化尋路**：
   - 捨棄傳統耗時之遞迴深度優先搜尋，改採基於壓縮稀疏列矩陣之二跳鄰域交集矩陣乘法。
   - 核心陣列記憶體自 NetworkX 的 1,581.41 MB 降至 56.74 MB（節省 93% 記憶體開銷）。
   - 純遍歷搜尋延遲自 749.95 ms 降至 0.067 ms（純遍歷提速 11,205.2 倍）；含動態建圖端到端延遲自 13,757.2 ms 降至 0.067 ms（端到端提速 205,550.2 倍）。
   - 經 18 組嚴格基準測試（涵蓋超巨型節點與各類邊界案例），達成 100% 拓樸集合雙射與數值等價性（100% PASS）。
2. **三態拓樸遮蔽狀態機**：
   - 嚴格對齊論文定義之解釋子圖聯集邊緣遮蔽干預。
   - 提供原始預測、遮蔽解釋子圖（必要性 F+）與僅保留解釋子圖（充分性 F-）三種狀態之動態視覺切換。
   - 搭配背景隨機神經網絡拓樸淡出與脈衝光流，精準傳遞圖神經網路之訊息傳遞因果關係。
3. **運算硬體職責解耦規範 (Hardware Decoupling)**：
   - 明確劃分離線學習與線上推論之硬體邊界：Intel Arc A750 GPU 僅用於離線模型訓練與注意力矩陣計算；線上路徑檢索與 CSR 雙向局部交集純粹於單執行緒 CPU (AMD Ryzen 5 7500F @ 3.70 GHz, 32 MB L3 快取) 與主記憶體 (32 GB DDR5) 中執行。
   - 藉由目標端雜湊集合 $\mathcal{S}_v < 2$ KB 完整常駐 CPU L1 快取與 CSR 連續陣列預取，實現輕量級 CPU 伺服器即可承載之低延遲（0.067 ms）線上服務，避免依賴高成本 GPU 實例。

### 4. 操作安全與連接埠規範 (Safety Standards)
- **避免端口衝突**：展示伺服器嚴格鎖定 8501 端口，代碼中內建保護機制，若誤設為 8000 端口將強制重設為 8501。
- **隱私脫敏與可移植性**：所有程式碼與腳本嚴格使用動態環境變數或相對路徑錨定，杜絕硬編碼開發者本機私有目錄。

---

## 影響與成效 (Consequences)
1. **模組職責清晰**：核心演算法開發與展示外殼完全解耦，`src/` 專注於論文實驗與評估，`demo/` 專注於口試互動呈現。
2. **口試現場零風險**：雙軌機制提供百分之百的現場容錯保障，無論會場網路狀況如何皆能流暢完成口試委員之提問互動。
3. **學術表達嚴謹**：全套介面與文件全面遵循專案學術標準，無中英名詞混用、無未加入元素贅述，具備高度學術專業度。
